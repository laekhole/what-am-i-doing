# waid — what am I doing?

여러 코딩 AI 세션의 **현재 작업, 프로젝트, 에이전트·모델, 마지막으로 확인한 상태**를 한 화면에서 보는 Windows 앱입니다. Claude Code·Codex·Copilot CLI 로그를 읽으며 에이전트에 명령을 보내지 않습니다. Kanboard나 일정 관리 없이 독립 실행합니다.

수집 결함 수정, 네이티브 UI, 사용자 템플릿을 구현한 개발 빌드입니다. **기본 화면과 템플릿 전환은 직접 확인했으며 키보드·혼합 DPI 검증은 남아 있습니다.** 자동 검사·실제 로그 대조·직접 화면 확인의 범위는 [검증 기록](VALIDATION.md)에 구분했습니다. 이전 설치본의 화면 확인을 이번 검증으로 간주하지 않습니다.

## Windows에서 실행

이 작업 환경에서 빌드한 앱:

```powershell
.\desktop\target\x86_64-pc-windows-gnu\release\waid-desktop.exe
```

같은 폴더의 `waid.exe`가 수집 코어입니다. 두 파일을 함께 두세요. 브라우저·Node·WebView2·Kanboard 서버는 필요 없습니다. 앱은 자신이 실행한 코어만 종료합니다. 이번 작업에서는 설치 파일과 포터블 ZIP을 갱신하지 않았습니다.

일반 Windows 개발 환경에서 빌드하려면 Rust와 해당 Windows 타깃의 링크 도구가 필요합니다. 저장소 루트에서:

```powershell
cargo test --release --locked
cargo build --release --locked
$env:WAID_CORE_PATH = Join-Path $PWD 'target/release/waid.exe'
cargo test --manifest-path desktop/Cargo.toml --release --locked
cargo build --manifest-path desktop/Cargo.toml --release --locked
.\desktop\target\release\waid-desktop.exe
```

GNU 타깃을 명시하면 양쪽 명령에 `--target x86_64-pc-windows-gnu`를 추가하고 코어·앱 경로에도 해당 타깃 디렉터리를 넣습니다. 이 PC의 로컬 도구 체인 재사용은 [검증 기록](VALIDATION.md)을 참고하세요.

## 화면 사용

기본 창은 **360×420 논리 픽셀**의 작은 창입니다. 각 세션을 휴대폰 알림처럼 둥근 카드로 표시하고, 앞에 하네스 로고를 둡니다. Codex는 OpenAI 마크, Claude Code는 Claude 마크로 구분하며 모델과 관계없이 하네스 ID로 선택합니다. 카드에는 작업 / 프로젝트·상태 / 에이전트·모델이 표시됩니다.

제목 표시줄에는 **항상 위**, **최소화**, **닫기**가 있습니다. 최대화 버튼과 최대화 동작은 제거했습니다. 제목 부분을 끌어 이동하고 가장자리를 끌어 크기를 조절할 수 있습니다.

- **항상 위**를 누르면 다른 일반 창보다 위에 유지합니다. 체크 표시로 켜짐을 확인합니다. 세션 **고정**과 별개입니다.
- **투명도 0%** 버튼을 누르면 슬라이더가 펼쳐집니다. 왼쪽은 선명, 오른쪽은 투명이며 **0~60%** 범위로 조절합니다. 항상 위·투명도는 재실행해도 유지합니다.
- **···**를 누르면 상세·검색·고정·종결·템플릿 버튼이 펼쳐집니다. 긴 요청은 목록을 더블 클릭하거나 Enter / 상세 버튼으로 확인합니다. 상세 화면에는 현재 요청, 대표 요청, 경로와 판정 근거가 있습니다. 요청은 최대 4,000자입니다.
- **검색** 또는 `Ctrl+F`로 확장 화면을 엽니다. 작업·프로젝트·모델·에이전트·폴더 검색과 상태·에이전트 필터를 함께 쓸 수 있습니다. **간단히** 또는 Esc로 작은 메모 크기로 돌아옵니다.
- **종결**(`Ctrl+D`)은 선택한 세션을 waid에서 정리하여 기본 목록에서 제외합니다. **전체 보기**에서 종결 표시로 확인하고 **되살리기**로 복귀시킬 수 있습니다. 유휴·응답 대기·프로세스 미발견만으로 자동 종결하지 않습니다.
- 종결한 세션에 **새 사용자 요청**이 기록되고 작업 중·내 차례·오류 상태로 관찰되면 자동 복귀합니다. 빨리 끝난 턴도 놓치지 않도록 내 차례를 포함합니다. 같은 문장도 이벤트 시각·ID가 다르면 새 요청입니다. 모델·비용 등 부가정보 갱신은 복귀 근거가 아닙니다.
- **고정**은 종결되지 않은 목록의 위에 유지합니다. 기존 **숨기기**(`Ctrl+H`)도 지원합니다. **전체 보기**에는 종결·숨김·보조 항목을 포함하며 검색·상태·에이전트 필터는 유지됩니다.
- 보조 세션은 기본적으로 숨깁니다. `보조 포함`을 켜면 하위 에이전트·자동 검토도 표시합니다.
- 갱신은 기본 2초 간격입니다. 선택·목록 상단·검색·필터를 유지합니다. 코어 오류 시 마지막 정상 목록과 오류 안내를 함께 표시합니다.
- 메모 최소 크기는 280×220입니다. 상세·검색·템플릿을 열 때만 800×640으로 확장하며 **간단히**로 이전 메모 크기로 복귀합니다. 확장 화면의 상세 영역은 창 너비에 따라 아래 또는 오른쪽에 배치합니다.
- `Tab / Shift+Tab`으로 이동, 목록에서 방향키·Page Up/Down, `Ctrl+F` 검색, `Ctrl+P` 고정, `Ctrl+H` 숨기기, 상세 텍스트 선택 후 `Ctrl+C` 복사를 사용합니다.

창의 항상 위·투명도, 검색·정리·적용 템플릿은 `%LOCALAPPDATA%\waid\settings.json`에 저장합니다. `WAID_DATA_DIR`로 폴더를 바꿀 수 있습니다. 원본 로그는 수정하지 않습니다. 같은 설정 파일을 쓰는 여러 창은 마지막 저장이 우선하므로 보통 한 창을 사용하세요.

템플릿은 **··· → 템플릿 → 기본 예제 복제 → 수정 → 미리보기 → 적용**으로 바꿉니다. [템플릿 안내](TEMPLATES.md)에 가져오기·내보내기·복구와 전체 필드 설명이 있습니다.

## 상태와 작업의 의미

| 화면 | 의미 |
|---|---|
| 내 차례 | 마지막 기록이 턴 종료입니다. 승인 요청 대기와 새 요청을 보낼 차례는 구분하지 못합니다. |
| 작업 중 | 최근 20초 안에 요청·작업 시작·도구 활동 등을 확인했습니다. |
| 중단 / 유휴 | 명시적인 중단 기록(turn_aborted, Copilot abort/shutdown 등)입니다. 프로세스 미발견으로 만들지 않습니다. |
| 오류 | 로그 이벤트 자체의 오류입니다. 도구 출력의 error 문자열만으로 판정하지 않습니다. |
| 미확인 | 해석할 상태가 없거나 작업 기록이 20초 넘게 갱신되지 않았습니다. 긴 도구 실행도 포함될 수 있습니다. |
| 종결 | 사용자가 waid에서 정리한 세션입니다. 원본 대화·프로세스는 종료하지 않습니다. 턴 종료와 구분합니다. |

Windows 앱은 **날짜 제한 없이 기존 로그도 수집**합니다. 앱 시작 이후 활동한 세션만으로 제한하지 않습니다. CLI는 기본 최근 24시간이며 `--history`를 넣으면 기간 제한이 해제됩니다. 현재 열린 창 목록이나 세션 생존을 보증하지 않습니다. JSON의 `alive: null`은 미확인입니다. 마지막 활동 시각은 이벤트 timestamp를 우선합니다. 비용·설정 갱신만으로 최근 대화나 재개라고 판단하지 않습니다. 날짜 없는 이벤트는 파일 시각에서 추정했다고 표시하며, 관찰 중 같은 이벤트 뒤에 붙은 부가정보는 활동 시각을 갱신하지 않습니다.

`task.text`는 읽기 범위에서 찾은 **최근 실제 사용자 요청**, `summary`는 앞부분의 첫 요청을 정리한 대표 요청(최대 200자)입니다. 최근 요청이 범위 밖이면 캐시된 요청을 유지합니다. 처음 읽을 때 첫 요청만 찾으면 `transcript_first_prompt`로 폴백 출처를 표시합니다. 발췌는 `≈`로 구분합니다. 명시적인 `WAID_TASK`·프로젝트 `.waid`·실행 인자 라벨은 계속 우선합니다. Windows에서는 조회 가능한 실행 인자의 라벨·모델 옵션을 사용합니다. 다른 프로세스의 환경은 읽지 않으므로 환경 라벨을 보장하지 않습니다.

종결할 때 요청 식별자와 짧은 세션 사본을 로컬에 저장하므로 원본이 사라져도 전체 보기에서 확인할 수 있습니다. 종결 기록은 최대 1,024개, 사본의 작업은 512자·대표 요청은 200자입니다. 현재 로그가 있으면 상세 내용은 수집한 값을 사용합니다. 날짜·이벤트 ID가 전혀 없는 동일 요청의 반복은 재개로 구별하지 못할 수 있습니다.

ID는 에이전트와 로그의 세션 ID에서 만들며 중복 ID는 합칩니다. Claude 보조 로그는 부모 ID를 공유하므로 파일 경로로 구분합니다. ID 없는 로그도 경로를 사용하므로 이동하면 고정·숨김 연결이 달라질 수 있습니다.

## 발견되지 않을 때

```powershell
.\target\x86_64-pc-windows-gnu\release\waid.exe doctor
```

기본 `~/.claude/projects`, `~/.codex/sessions`, `~/.copilot/session-state`와 명시된 `CODEX_HOME/sessions`, `COPILOT_HOME/session-state`를 읽습니다. 앱 실행 프로세스에 환경변수가 전달되어야 합니다. 다른 경로는 [사용자 어댑터](CLI.md#에이전트-추가하기)를 설정하세요. 같은 이름의 사용자 어댑터는 내장 정의를 대체합니다.

Windows에서는 이름·PID를 열거하고 알려진 실행 파일·Node/Python 등 인터프리터에 한해 읽기 전용으로 실행 인자를 조회합니다. 권한이 없거나 지원하지 않는 실행 방식이면 이름 감지로 폴백합니다. 작업 디렉터리는 조회하지 않아 프로세스와 개별 로그를 확실히 연결하지 못합니다. 읽기 권한·지원하지 않는 형식·큰 단일 레코드 때문에 누락될 수 있습니다. 로그는 앞 128 KiB, 뒤 256 KiB까지만 읽습니다. 개별 파일 읽기 실패의 UI 알림은 아직 지원하지 않습니다.

## 에이전트별 지원 범위

| 에이전트 | 실행 감지 | 저장된 작업·모델·상태 |
|---|---|---|
| Claude Code, Codex | 지원 | 지원 |
| Copilot CLI | 직접 실행·Node 패키지 | session-state의 events.jsonl 지원 |
| Gemini CLI, OpenCode | 직접 실행·Node/Bun 패키지 | 아직 미지원 |
| Aider | 직접 실행·Python 스크립트·python -m aider | 아직 미지원 |
| Cursor CLI, Goose | cursor-agent / goose 실행 파일 | 아직 미지원 |

프로세스만 발견하면 상태는 **미확인**입니다. 모델은 실행 인자에 명시된 경우만 표시합니다. Cursor 편집기·VS Code 확장 에이전트는 CLI와 별개이며, WSL 내부 프로세스 감지는 Windows에서 지원하지 않습니다. Copilot의 경로·이벤트 정책은 [CLI 안내](CLI.md#지원-에이전트)를 참고하세요.

## CLI와 문서

```text
waid                  표 한 번 출력
waid --json --watch   JSON 스트림
waid --json --history 이전 날짜의 세션도 포함
waid --waiting        사용자 차례만
waid --agent claude   특정 에이전트
waid --html --watch   로컬 HTML 대시보드
waid doctor           경로·어댑터·프로세스 진단
```
